# EPUB 屏幕页码设计

## 背景

当前 EPUB 阅读器底部页码和目录页码使用“文本位置桶”：按文本长度估算位置，而不是按当前阅读器排版后的可见屏幕计算。用户在分页、双页或滚动阅读时，会看到内容已经移动很多屏，但页码只变化少量，容易误解为翻页或同步错误。

本设计把 EPUB 的显示页码重新定义为“当前阅读器排版下的屏幕页码”。页码用于显示和辅助跳转；保存进度、书签、标注、AI 阅读笔记定位继续使用 CFI，保证窗口和排版变化后仍能稳定回到内容位置。

## 用户规则

- 单页分页模式：一屏显示一页，翻一屏页码加 1。
- 双页分页模式：一屏显示左右两页，翻一屏页码加 2。
- 滚动模式：按当前阅读器可见高度切分，一屏高度算一页。
- 目录右侧页码使用全书累计屏幕页码。
- 底部页码使用全书累计屏幕页码。
- 页码随窗口大小、字号、行距、页边距、宽度模式、单双页、滚动/分页模式变化而重新计算。

## 显示规则

底部页码：

- 单页模式显示 `第 10 / 214 页`。
- 双页模式显示页码范围，例如 `第 10-11 / 214 页`。
- 滚动模式显示当前滚动位置对应页，例如 `第 10 / 214 页`。
- 全书屏幕页数未完全计算完成时，显示当前可用估算并保持阅读器可操作。

目录页码：

- 目录项右侧显示该目录项在当前排版下的全书累计页码。
- 双页模式下，如果目录项落在右侧栏，显示对应的右栏页码。
- 页码尚未计算完成的目录项先显示加载态或暂不显示，计算完成后局部刷新。

跳转：

- 底部输入“页码”时，按当前屏幕页码跳转。
- 跳转时把目标页映射回该页开头附近的 CFI，再交给阅读器定位。
- 如果目标页映射暂未计算，先触发对应章节计算，再跳转。

## 架构

新增一个 EPUB 屏幕分页索引层，职责是把“当前排版配置 + 全书章节”映射为屏幕页：

- `layoutKey`：由窗口尺寸、字号、行距、字距、页边距、宽度模式、布局模式、阅读模式组成。
- `chapterPageIndex`：每章的页数、起始全书页码、章节内页到 CFI 的映射。
- `tocPageIndex`：目录 href 到全书页码的映射。
- `currentPageRange`：当前可见区域对应的全书页码或页码范围。

阅读器服务负责：

- 监听 Foliate relocate、load、layout 变化。
- 计算当前章节的真实屏幕页码。
- 后台逐章构建全书页码索引。
- 在索引变化时通知底部导航和目录刷新。

UI 负责：

- 底部导航展示屏幕页码和页码范围。
- 目录展示屏幕页码。
- 页码计算中保持可读可翻页，不阻塞阅读。

## 性能策略

不能一次性同步重排全书。实现必须遵守：

- 当前章节优先计算，保证底部页码尽快正确。
- 其他章节后台分批计算，每批让出主线程。
- 计算结果按 `layoutKey + book source id` 缓存。
- 排版设置或窗口尺寸变化时废弃旧 `layoutKey` 的显示索引，启动新索引。
- 如果用户快速切书或切设置，取消旧任务，避免过期结果覆盖当前书。

## 数据边界

屏幕页码不写入永久阅读进度，不替代 CFI。

可以缓存：

- 当前布局下的章节页数。
- 目录项页码。
- 页码到 CFI 的近似映射。

不可依赖缓存：

- 书签真实定位。
- 标注定位。
- AI 阅读笔记来源定位。

这些仍以 CFI、章节 href、source locator 为准。

## 错误处理

- 某章计算失败时，该章目录页码显示为空或估算值，阅读器继续可用。
- 页码跳转目标未计算成功时，提示“正在计算该页位置”，完成后跳转。
- 布局变化时不阻塞阅读，只逐步刷新页码。
- 如果 Foliate 无法提供足够布局信息，回退到当前文本位置估算，但 UI 需要避免误称为已精确计算。

## 测试

需要覆盖：

- 单页模式下，一屏对应一个全书页码。
- 双页模式下，当前可见页显示为范围，下一屏页码加 2。
- 滚动模式下，按视口高度映射页码。
- 目录项使用全书累计屏幕页码。
- 布局变化后旧索引不再覆盖新索引。
- 后台计算不会阻塞当前章节页码更新。
- 页码跳转映射到对应 CFI。

## 第一版范围

第一版只实现 EPUB 屏幕页码索引、底部页码、目录页码和页码跳转。阅读进度存储、书签、标注、AI 阅读笔记定位不改存储语义。
